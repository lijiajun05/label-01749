# 班级事务与学风管理系统

## 运行方式

### 方式一：Docker Compose 一键启动（推荐）

#### 环境要求
- Docker 20.10+
- Docker Compose 2.20+

#### 快速启动

1. **克隆项目**：

```bash
git clone <repository-url>
cd label-01749
```

2. **启动所有服务**：

```bash
docker-compose up -d
```

3. **访问系统**：

- 管理后台：http://localhost:8081
- 后端 API：http://localhost:8080/api
- MySQL数据库：localhost:3306

#### 常用命令

```bash
# 启动服务
docker-compose up -d

# 查看服务状态
docker-compose ps

# 查看服务日志
docker-compose logs -f [服务名]

# 停止服务
docker-compose stop

# 停止并删除容器
docker-compose down

# 停止并删除容器和数据卷（谨慎使用，会删除所有数据库数据）
docker-compose down -v
```

#### 数据库初始化
系统启动时会自动执行 `mysql/init/init.sql` 脚本初始化数据库表结构和数据。

### 方式二：本地开发启动

#### 环境要求
- JDK 17+
- Maven 3.8+
- Node.js 18+（建议 20 LTS）
- MySQL 8.0

#### 启动步骤

1. **准备数据库**：创建数据库与用户（与下方「数据库连接信息」一致），并执行 `mysql/init/init.sql` 初始化表结构与数据。

2. **启动后端**（默认 `dev` 配置，连接本机 MySQL）：

```bash
cd backend
mvn spring-boot:run
```

3. **启动前端**：

```bash
cd frontend-admin
npm install
npm run dev
```

## 题目内容

一、课题研究背景意义及现状 
随着高校信息化与数字校园建设的不断推进，学生管理模式正由传统的经验型管理逐步向数据化、精细化管理转变。班级作为高校教学与学生管理的基本单元，承担着学风建设、事务管理与学生日常教育的重要职能。然而在实际运行中，班级事务与学风管理仍以人工统计和分散化工具为主，普遍依赖微信群、Excel表格及线下通知等方式，存在信息碎片化、数据难以长期积累、统计效率低下及反馈滞后等问题，难以满足当前高校管理对及时性与准确性的要求。 
从学风管理角度看，学生考勤、作业完成情况与课程成绩是反映学业状态的重要指标，但在传统管理模式下，这些数据往往分散在不同系统或由教师个人保管，缺乏统一整合与持续分析机制，导致学业风险识别主要依赖教师经验判断，预警不及时，干预手段缺乏针对性。同时学生对自身学习状况的认知多停留在单次成绩层面，缺少对长期学习趋势的直观了解，不利于自我管理能力的提升。 
在研究现状方面，国内高校已逐步引入教务管理系统、智慧校园平台和学习管理系统，在课程管理、成绩录入等方面取得了一定成效。但现有系统多侧重教学业务流程，关注学校或学院层面的宏观管理，对班级层面的事务协同与学风精细化分析支持不足。此外，部分系统功能分散，角色协同程度有限，难以从班主任、任课教师和学生多视角对班级学风进行综合呈现。在可视化与预警机制方面，仍以简单统计展示为主，缺乏针对班级学风建设的专门设计。 
基于上述背景，开展班级事务与学风管理系统的研究具有重要的理论与实践意义。本课题基于Java与MySQL技术，围绕班级管理、学风跟踪和事务提醒等核心需求，构建多角色协同的信息化管理平台。通过引入学风数据仪表盘和多种统计图表，实现学业数据的直观展示与趋势分析，并结合预警与提醒机制，提高学风管理的前瞻性和精准性。该研究有助于弥补现有系统在班级层面管理中的不足，为高校推进精细化育人和学风建设提供可行的技术路径与实践参考。 
二、课题需要研究或解决的问题及拟采用的方法 
1、系统的组成及功能构想 
1.1系统总体架构设计 
系统采用Java+Vue+MySQL的前后端分离架构，后端负责业务逻辑处理与数据持久化，前端实现交互界面与数据可视化展示，提升系统的可扩展性、维护性与响应效率，满足班级管理的长期使用需求。 
1.2班级管理模块功能构想 
该模块用于规范班级基础信息管理，支持班委成员信息维护、班会记录录入与查询以及班级通讯录统一管理，方便班主任与学生快速获取班级组织结构和重要历史记录，提升班级日常事务管理的规范性。 
1.3学风跟踪与分析模块功能构想 
系统通过采集考勤数据、作业提交情况和课程成绩信息，对学生学习状态进行统计分析，生成个人与班级层面的学风指标，为班主任及时掌握学习情况、发现潜在学业风险提供数据支持。 
1.4学业预警与反馈功能构想 
针对作业长期未交、出勤率偏低或存在挂科风险的学生，系统自动触发预警提示，并向班主任和学生反馈相关信息，帮助管理者及早干预，促进学生调整学习状态，提升整体学风质量。 
1.5事务提醒与信息发布模块功能构想 
系统支持缴费通知、评奖评优、公示信息及集体活动安排的统一发布，通过弹窗与消息提醒方式推送给学生，确保重要事务及时传达，减少遗漏，提高班级事务处理的效率与透明度。 
2、系统其它方面的初步设想 
2.1数据统计与可视化展示设想 
通过对学风与事务数据的汇总分析，系统以柱形图、折线图和饼图等方式直观呈现变化趋势，帮助管理者快速理解班级运行状况，提升数据解读效率与管理决策的科学性。 
2.2系统安全与数据备份设想 
系统在登录认证、数据传输和数据库访问等环节引入安全控制机制，并定期进行数据备份，防止信息泄露或数据丢失，保障学生个人信息与班级数据的长期安全。 
2.3使用体验与人性化设计设想 
系统界面设计注重简洁清晰，操作流程贴近班级管理实际，支持消息提醒与快速查询功能，降低使用门槛，使班主任和学生均能轻松上手并长期稳定使用。 
3、环境要求 
3.1硬件环境要求 
系统部署对硬件要求较低，服务器端可运行在普通PC服务器或云服务器环境中，建议配置双核及以上CPU、8GB内存和充足磁盘空间，以满足并发访问和数据存储需求；客户端支持PC与移动设备通过浏览器访问。 
3.2软件环境要求 
服务器操作系统可采用Windows系统，后端运行环境需支持Java运行时环境，数据库采用MySQL；客户端通过主流浏览器访问系统，确保良好的兼容性与稳定性。 
3.3开发环境要求 
系统开发推荐使用IntelliJ IDEA作为后端开发工具，配合Maven进行项目管理，前端采用Vue开发框架与常用组件库，数据库设计与管理可使用Navicat等工具，提升开发与调试效率。 
4、本系统拟采用的解决方法（技术） 
本系统拟采用基于Java的分层开发模式作为主要解决方法，后端利用Hibernate实现对象关系映射，简化数据库操作并提高数据一致性，通过REST接口向前端提供统一的数据服务；前端采用Vue框架构建交互式界面，实现组件化开发与数据的动态展示；数据库使用MySQL存储班级事务与学风数据。系统结合数据统计与可视化技术，将考勤、作业与成绩信息转化为直观图表，并通过消息提醒机制实现事务的及时推送，从而提升班级管理的效率与科学性。
